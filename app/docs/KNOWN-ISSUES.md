# Known issues

Faults in the application template found by an external security audit. They change no protocol rule. Fix them before anyone forks `app/`. The audit's proofs of concept are not part of this repository, so each fix has a test written here that reproduces the attack, fails before the fix and passes after it.

| ID | Severity | Issue | Fix | Status |
| --- | --- | --- | --- | --- |
| H7 | High | The email bridge is an open phishing relay: a key principal minted a second earlier counts as a verified person, so any leased agent makes the server email anyone from its domain. | Key principals do not count as verified people for the bridge; require an email- or phone-verified principal or the host's approval; limit bridged recipients per person and per day. | Fixed |
| H8 | High | SMS and email pumping: one owner session sent codes to 100 phone numbers, because limits are per destination only. | Budgets per session, per person, per source network and in total, with alerting; refuse premium-rate ranges. | Partly fixed: budgets per session, per person and server-wide. Still open: a per-network budget, and refusing premium-rate ranges (left to the operator). Anyone can spend the server-wide SMS budget, which stops SMS codes for everyone until the day turns |
| H9 | High | One agent's slow webhooks stall every module: webhooks, bridged mail, introductions and releases share one sequential queue. | Webhooks get their own queue; jobs run concurrently with a per-owner share; short webhook timeouts and quick back-off. | Fixed |
| H10 | High | Blocks are bypassed through introductions: a blocked sender reached the target through a carrier it only claimed to know. | Apply the target's blocks before an introduction is offered and before its brief is shown; define "contact" by the carrier's own edge, not the requester's claim. | Fixed |
| M12 | Medium | Whoever later holds one recycled identifier acts as the whole person: changes person-wide settings, finds unlisted friends, sees the person's other email. | Scope person-wide settings to sessions that prove a current primary identifier; re-prove identifiers gone dormant; never present an identifier the session did not prove. | Fixed |
| M13 | Medium | Messages held by inbound limits are released the next day without running the rules again, even after a block. | Run every rule, blocks included, before releasing a held message. | Fixed |
| M14 | Medium | A stranger learns which email domains a listed person verified, from the provenance on the stranger's own pending attestation. | Compute no provenance against the subject's identifiers for facts still pending. | Fixed |
| M15 | Medium | Agent cards may publish `javascript:` URLs: stored XSS for any interface that links them. | Accept only `https:` card URLs (`http:` in development). | Fixed |
| M16 | Medium | The plain-text contact filter is bypassed with Unicode lookalikes (`evil․com`, full-width digits). | Normalise with NFKC and a confusables map before matching. | Fixed |
| app L1 | Low | Retirement and erasure leave raw identifiers behind, in `policy.contacts`, `intros.requests`, `policy.entries` and `owner.logins`; this is also why `test/privacy.test.ts` is flaky. | Write no contacts for retired agents; hash addresses in surviving records; delete `owner.logins` on erasure; make the test settle queued work before it checks. | Fixed, including the racy test, which now waits for queued work to settle. Left over: a sign-in the person never finished keeps its raw identifier until it expires and is pruned |
| app L2 | Low | `resolve` shows whether a listed target has an edge to the asker. | Answer the same whether or not the edge exists. | Design tradeoff: the `connections` tier; not changed |
| app L3 | Low-Medium | Sign-in codes allow 25 to 35 guesses per identifier per hour, renewed every hour, on six-digit codes: about 20% a year against one targeted identifier. | A long-term ceiling per identifier, with a lockout the identifier's owner is told of. | Fixed (eight-digit codes) |
| app L4 | Low | `resolve` timing differs between nobody and an unlisted member (1.03 ms against 1.43 ms). | Do the same work in both cases. | Open; low (about 0.45 ms in process), bounded by the discovery budget |
| app I2 | Info | The anonymous card route returns `keys` and `createdAt`, against the README. | Remove them, or correct the README. | Open |
| app I4 | Info | A self-registered OAuth client gets the whole `owner` scope, including API keys valid for a year. | Narrower scopes for third-party clients. | Open |
| client-api I11 | Info | `skill/reference.md` tells an agent to cancel any recovery it did not start, which helps a thief. | Tell the agent to report the notice to its principal instead. | Fixed (`skill/reference.md` now cancels only when the principal asks) |

The template's email bridge should also move to the bridge interface of [docs/MODULES.md](../../docs/MODULES.md), and its pairing to key principals by default ([docs/ROADMAP.md](../../docs/ROADMAP.md), "Privacy and erasure").
